# One-file CodePad master

Download LAST_LIGHT_MASTER.py and open it in the same CodePad environment that ran V4 with Pillow. No neighboring Python files, source downloads, network account or terminal installation are required. Optional CUSTOM_WORK_FOLDER selects a persistent Files-accessible destination.

The default run exports the complete catalog audit and2,745 remaining identity-bound design briefs, then generates/resumes the24 completed demo sprite designs. Output is under Documents/LAST_LIGHT_MASTER when permitted; the program prints the actual destination. The source review CSV is in source_checks/, the design queue in design_queue/, and individual sprites/contact sheets/ZIPs in approved_style_demo/. User-edited design queues are preserved with versioned exports.

The109 previously reported passes were tests, not sprites. The2,745 entries are source-linked brief drafts, not finished drawing recipes. This file does not yet generate2,745 new sprites. It preserves the exact working V4 renderer and native templates; new identities need independently authored artwork/geometry and identity/visual review. No templates are relabeled or source pixels repurposed.1,578 remaining source exceptions stay recorded.

Actions:setup_and_demo (default), catalog_only, demo_only, render_recipes. Catalog rendering requires finished original-art recipes with exact source IDs and a verified classification ledger; existing V4 gates are retained. Source-less demonstrations cover zero catalog records. No automatic mass promotion or new founder/art/device approval occurs.

Developer commands:

```sh
python tools/build_unified_phone_master.py
python LAST_LIGHT_MASTER.py --output /persistent/LAST_LIGHT_MASTER
python tests/unified_phone_master_test.py
```

Actual tests verify standalone execution, all24 unchanged PNG hashes, resumption, all2,745 queue entries, preservation of edited queues and rejection of wrong/source-less identities. The combined file was executed on Linux; it still requires execution in the user's CodePad environment to verify this wrapper on iPhone. The embedded V4 renderer already has user-reported successful iPhone execution.

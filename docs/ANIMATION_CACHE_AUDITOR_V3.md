# LAST LIGHT — LL-074 / LL-070 / LL-071 verified-cache handoff and animation audit V3

**Scope:** Independent, read-only source-media forensics; no PZwiki retrieval, image redistribution, gameplay scene changes or Golden 40 visual approval. Built on [Animation Auditor V2](ANIMATION_AUDITOR_V2.md). The frozen **21,025 File-namespace IDs** belong to the retrieval worker; this adapter neither edits nor replaces that census.

## Required handoff from the retrieval developer

Provide an **explicit existing cache path**, a **versioned verified manifest** and immutable source media under that root. Never invent a path or assume that a retrieval archive exists merely because a screenshot reports cached files. Cache integration begins only after the retrieval worker exposes real local bytes.

Accepted formats: JSONL (`.jsonl`, one object per line) or read-only SQLite (`.sqlite`, `.sqlite3`, `.db`) with a `verified_media` table. Each row must have the following fields:

```json
{"schema":"last_light.verified_cache_entry.v1","source_id":"pzwiki.file.000123","relative_path":"images/Example.gif","sha256":"<64-character lowercase hex SHA-256>","byte_length":12345,"mime":"image/gif","category":"animation_reference","rights":"research_only","retrieved_at":"2026-11-07T00:00:00Z","verification_status":"verified"}
```

- `source_id`: stable worker-owned source identity; never rewritten or regenerated by the auditor.
- `relative_path`: strictly relative POSIX path inside the authorized cache root; no `..`, absolute path, URI or symlink component.
- `sha256` and `byte_length`: computed by the retrieval worker over the actual stored bytes, and rechecked before analysis.
- `mime`: declared content type; cross-checked with decoded file signature. Unsupported/non-image types are rejected.
- `category`, `rights`, `retrieved_at`: explicitly supplied provenance; never inferred from a GIF extension.
- `verification_status`: must be `verified`; partial/pending retrievals remain unavailable.

For SQLite, create `verified_media` with column names matching these JSON keys and use text/integer types as appropriate. `schema` is part of each row. The adapter opens SQLite with `mode=ro`; JSONL is only read.

## Run without touching cache contents

```bash
python tools/last_light_animation_auditor.py \
  --cache-manifest /private/retrieval/verified.jsonl \
  --cache-root /private/retrieval/media \
  --output-dir /private/last-light-derived/animation-audit \
  --resume --max-files 100
```

Remove `--max-files 100` once a reviewed benchmark is satisfactory. Other supported options: `--max-frames 512`, `--max-canvas-pixels 16000000`, `--max-total-pixels 64000000`, and previous V2 `--input-zip`, `--input-dir`, and `--catalog-dir` inputs. Valid ZIPs are processed without extraction; the separate worker cache should use the verified manifest path instead.

The output directory **must be outside the cache root**. The auditor writes only to the output directory:

- `animation_audit_checkpoint.sqlite3`: source-ID + independently verified SHA-256 + auditor-version checkpoint. A rerun with `--resume` hashes source bytes before reusing a cached inspection; changed files are not silently reused.
- `animation_inventory.jsonl` / `.csv`: per-file decoded media details and structured `error_code`.
- `animation_report.json`: totals, failures, duplicate byte hashes, source-catalog coverage and cache reuse.
- `missing_catalog_records.csv`, `numbered_frame_sequences.json`: metadata coverage and possible frame sets.

## Media and timing verification (LL-070 / LL-071)

- Independently verify every supplied SHA-256 and byte count. Error codes include `CACHE_HASH_MISMATCH`, `CACHE_SIZE_MISMATCH`, `CACHE_MIME_MISMATCH`, `CACHE_SYMLINK_REJECTED`, `UNSAFE_CACHE_PATH`, `CACHE_FILE_MISSING`, `CACHE_NOT_VERIFIED` and `DUPLICATE_CACHE_SOURCE_ID`.
- Decode GIF, APNG and animated WebP when supported by the installed Pillow codec. Compare declared extension/MIME with actual decoder format; record per-frame delay, disposal, blend operation, alpha bounds, duplicate-frame indices, loop metadata and timing warnings.
- Reject file/frame pixel resource overages before full frame decoding: `RESOURCE_LIMIT_CANVAS` or `RESOURCE_LIMIT_FRAMES`. Capture corrupt images as structured failures and continue the batch.
- A file named `.gif` is not necessarily multi-frame. Wide single PNG strips remain only `possible_sprite_sheet_unverified`. `held_00`–`held_07` sets are directional poses, not temporal motion. Do **not** turn duration metadata into a definitive gameplay FPS or assume looping/one-shot semantics without an approved state contract.
- Per-frame visual contact sheets, ground-anchor jitter, state transitions, Golden 40 artistic approval, actual Godot import and Xogot/iPhone device testing remain separate LL-072–LL-080 work. Source references are research-only unless specific licensing establishes otherwise.
